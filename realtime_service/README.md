# SearchOrders Live · MVP

Небольшой сервис мониторинга **публичных Telegram-каналов** для независимого дизайнера (https://samsel.site).

## Что уже работает
- Опрос каналов из `data/search_sources.json` каждые 5 минут (по умолчанию 16 Telegram-источников).
- Получение даты и прямой ссылки на опубликованное сообщение; фильтры свежести до 72 часов.
- Эвристическая проверка запроса по четырём категориям: сайты, UI/UX, презентации, брендинг/графика.
- Отсев очевидного спама, саморекламы и штатных вакансий. Внимание: фильтр не является гарантией наличия оплаченного заказа.
- Извлечение публичного Telegram/email-контакта, сохранение в SQLite, удаление дублей.
- Локальная веб-панель с поиском, рейтингом, ссылкой на оригинальный Telegram-пост, статусами «Новый/Избранное/Написал/Скрыть».
- **Кнопка «✦ Сформировать отклик»** в карточке любого заказа. Сервис составляет черновик на русском из конкретного текста объявления, адаптирует аргументы под сайты/Tilda, UI/UX, презентации, айдентику, маркетплейсы и упаковку, добавляет ссылку https://samsel.site. Письмо открывается в редактируемом поле; кнопка «Копировать письмо» переносит его в буфер обмена. Отправка только вручную.
- Генератор пока локальный, на правилах и ключевых словах, **без внешнего AI API**. Не проверяет личность заказчика и не придумывает подтверждённый опыт: черновик нужно просмотреть перед отправкой.
- Локальные уведомления macOS о новых свежих кандидатах и опционально сообщения через Telegram-бота (при подключённом боте).
- Добавление новых публичных Telegram-каналов через интерфейс.
- Записи уже контактированных пользователей из `data/outreach_status.json` повторно не включаются.
- **Никаких автоматических откликов заказчикам или обхода авторизации в закрытых каналах.**

## Запуск на Mac

```bash
cd ~/Projects/searchorders
python3 -m pip install -r requirements.txt
python3 -m realtime_service.app
```

Открыть http://127.0.0.1:8787.

В фоне при входе в macOS: `~/Library/LaunchAgents/site.samsel.searchorders.plist` (установить через `launchctl bootstrap gui/$(id -u) ...`).
Пока Mac спит или выключен, мониторинг не работает.

## Уведомления в Telegram

1. Создать личного бота у @BotFather, получить токен.
2. В панели «Уведомления» сохранить токен.
3. В Telegram открыть своего бота и отправить `/start`.
4. В панели нажать «Найти чат», затем «Тест».

Токен хранится в `.runtime/settings.json` (права 0600), никогда не в Git. Если Telegram не подключён, заказы продолжают собираться в интерфейсе.

## Данные и приватность

База `.runtime/leads.sqlite3` не коммитится. В ней только публичные записи и выбранные статусы. Панель по умолчанию слушает **127.0.0.1**, без публичного доступа и без регистрации. Для VPS необходимы HTTPS, авторизация и постоянный диск.

## Запуск в Docker (на VPS)

```bash
docker compose -f realtime_service/docker-compose.yml up -d --build
```

Внешний порт намеренно закрыт для Интернета: доступ через SSH-туннель или настроенный безопасный reverse proxy. Без настроенной авторизации не публиковать панель напрямую.

## Ограничения MVP

- «Почти реальное время» означает polling каждые 5 минут, а не гарантированную мгновенную доставку.
- Поддерживаются 16 публичных Telegram-источников, а не все социальные сети Shikari.
- Перепост может иметь свежую дату при старом исходном заказе: дата на карточке относится к Telegram-сообщению, окончательная проверка первоисточника и клиента вручную.
- Публичный @username — не доказательство того, что автор действительно заказчик.
- Поиск отбирает **кандидатов**, не гарантированно оплачиваемые заказы. Перед откликом проверить бюджет, ТЗ, клиента и контакт.
- Для круглосуточной работы нужен VPS или иной постоянно работающий хост.
- Штатную занятость и предложения без прямых контактов отсекаем, но ложные срабатывания возможны. Статус «Скрыт» помогает обучать правила следующими итерациями.

Сервис не отправляет заявки клиентам автоматически. Решение и отправка остаются за пользователем.

## Индивидуальная генерация откликов (2026-10-29)

Кнопка «Сформировать отклик» сначала извлекает из конкретной публикации задачи, объём, платформы, сроки и ограничения, затем создаёт короткое письмо от независимого дизайнера. Бренды Avito/Haval не подставляются автоматически. Черновики **никогда не отправляются** в Telegram или email без действия пользователя.

- **Локальный режим:** без AI API автоматически формируются варианты по деталям исходного объявления, с сохранением истории. Это алгоритм, а не языковая модель; качество естественного языка ограничено.
- **ИИ-режим:** открой «Уведомления» → «ИИ для индивидуальных откликов», вставь свой OpenAI API key из https://platform.openai.com/api-keys и нажми «Сохранить». Ключ хранится локально в `.runtime/settings.json` с правами 0600, не передаётся браузеру в ответе API и исключён из Git. ChatGPT Plus не заменяет ключ API: использование OpenAI API тарифицируется отдельно.
- ИИ получает исходное объявление и несколько предыдущих вариантов отклика, чтобы каждый раз писать новый, короткий и специфичный текст. Ответ проходит дополнительную проверку на повторы и лишние утверждения.
- История генераций сохраняется в SQLite-таблице `draft_history` и переживает перезапуски сервиса. Кнопка «Сформировать заново» всегда обращается к серверу и создаёт новую запись.
- Если подключение к ИИ отсутствует или недоступно, интерфейс показывает «Локальный вариант», а не утверждает, что текст написал ИИ.
- Настройки модели: по умолчанию `gpt-4.1-mini`, можно сменить в панели (модель должна быть доступна по API-ключу).

### Статусы откликов

Статус переписки **«Не написал» (красный)** / **«Написал» (синий)** отмечается вручную: открытие Telegram с подготовленным черновиком не означает отправку. Кнопка «Отметить: написал» меняет статус, повторное нажатие позволяет вернуть «Не написал». Избранное является отдельным независимым флагом, отметка о переписке не пропадает при сохранении заказа. Ранее помеченные как «Написал» или «В избранном» заявки мигрируют из старой схемы автоматически без потери данных.

### Главная лента и архивы — 29 октября 2026

- Главная `/` показывает **только необработанные заказы**. Объявления с отметкой «Написал» и скрытые исключены, в том числе если заказ перепубликовали с новой ссылкой, но тем же контактом.
- **«↻ Новый поиск заказов»** на главной заново опрашивает все 16 подключённых публичных источников и после завершения обновляет ленту; старые отмеченные/скрытые заказы остаются в базе, но не появляются в главной ленте.
- Отдельная страница `/contacted` — **«Написал»**: только заказы с подтверждённой вручную отметкой о переписке. Нажатие «Отметить: написал» автоматически удаляет карточку из главной ленты и переносит в эту историю. Отменить отметку можно здесь же.
- `/saved` — избранное; `/hidden` — скрытые объявления. Скрытый заказ можно восстановить; статусы избранного и переписки не стираются.
- После любой отметки список и статистика обновляются с сервера, а не только перекрашиваются в браузере. Отправка сообщения **не автоматизируется**, отметка «Написал» подтверждается пользователем.
- Блокировка новых перепубликаций использует публичный контакт из объявления, поэтому новый проект от того же контакта тоже будет исключён, пока заказ помечен «Написал» или скрыт. Это соответствует требованию не предлагать уже обработанных клиентов.

### Email-first отклики — 29 октября 2026

После ограничения Telegram для новых контактов основной интерфейс переключён на отклики **по электронной почте**:

- Главная `/` показывает только необработанные объявления с **реальным опубликованным email**, не Telegram-логинами. Текущий Telegram-мониторинг собирает такие объявления редко; нулевая email-лента честно показывает отсутствие результатов, а не создаёт вымышленные адреса.
- `/without-email` содержит объявления с Telegram-контактом, доступные для просмотра, но **без возможности сформировать/отправить email на несуществующий адрес**.
- В карточке email-заказа — отправитель `cco@imon.agency` (справочно), получатель, отдельно редактируемая тема и тело письма. Тема создаётся по конкретной задаче. История предыдущих генераций сохраняется.
- Кнопка «Открыть в почтовой программе» формирует `mailto:` с опубликованным email, темой и текстом. Это открывает **черновик, а не отправляет письмо**. Почтовый клиент может выбрать адрес отправителя по умолчанию, поэтому обязательно проверить, что отправитель `cco@imon.agency`.
- «Копировать письмо» копирует адрес, тему и текст; «Яндекс Почта» открывает корпоративную веб-почту для ручной отправки.
- Кнопка «+ Добавить заказ по email» позволяет добавить реальное опубликованное объявление с прямым email, ссылкой и текстом ТЗ. Сервис сохраняет его в базе и исключает дубли. Дату ручного добавления не следует считать датой оригинальной публикации.
- «Написал» выставляется только вручную **после фактической отправки письма**, затем заказ исчезает из главной ленты и переходит в `/contacted`.
- Сканирование 16 публичных Telegram-каналов и уведомления продолжают работать. Поиск новых email-источников и облачное развёртывание — отдельная задача; они не входят в этот UI-релиз.

### Новые email-источники (29 октября 2026)

Сервис теперь регулярно проверяет **18 источников**: 16 существующих публичных Telegram-каналов и две независимые публичные площадки с email-контактами:

1. **The Pending Agency Opportunities** — https://agency.thepending.com/jobs/ — проверяются карточки, где одновременно присутствуют дизайн-задача, фриланс/контракт, открытая дата отклика/проекта и адрес для отклика, действительно указанный в тексте конкретной заявки. Не проходят объявления с обязательным нидерландским языком, штатной занятостью без freelance и истёкшими дедлайнами. Объявления о будущем партнёрстве помечаются отдельно пониженным рейтингом и явным предупреждением, что текущий оплаченный проект не подтверждён.
2. **Impactpool, проверенный публичный тендер на графический дизайн Transparency International** — https://www.impactpool.org/jobs/1243128 — включается в поиск только пока действительно открыта подача до 2026-10-31 и сайт явно указывает адрес для заявок. Адрес не берётся из подвала сайта.

Проверка новых площадок выполняется автоматически каждые **15 минут** при работающем Mac, а не при каждом 5-минутном опросе Telegram. Кнопка «Новый поиск заказов» позволяет запустить повторную проверку после короткого защитного интервала. Состояние каждого источника и ошибки фиксируются в таблице SQLite `email_source_checks` и доступны через `/api/status`.

**Подтверждение актуальности:** если есть дата окончания приёма заявок, она сохраняется в `expires_at`; по наступлении даты в прошлом объявление перестаёт отображаться в основной email-ленте. Если оригинальная дата публикации не указана, `published_at` означает время первого обнаружения сервисом, а интерфейс подписывает его «Обнаружено сервисом». Никаких дат свежести мы не придумываем.

Новые англоязычные объявления получают **англоязычные отклики**, а тема письма берётся из прямых инструкций заказчика (например, `Freelance Graphic Designer`), если она указана. История генераций и ссылка на https://samsel.site сохраняются.

Ограничение: это два проверенных новых источника, а не полноценный поиск по всему Интернету. Конкретные вакансии могут закрыться раньше даты публикации, поэтому перед отправкой нужно проверить первоисточник. Письма автоматически не отправляются.

### Переключение каналов и отправителя (29 октября 2026)

- На главной панели над фильтрами теперь есть переключатель **«✉ Почта / ◉ Telegram»**. Почта показывает только необработанные заявки с публичным email (`/`), Telegram — только заявки с Telegram-контактом (`/without-email`). Разделы «Написал» и «Скрытые» общие. Переключение не сбрасывает статусы, источники, архивы и историю писем.
- В готовом email-отклике поле **«От»** стало выпадающим списком: `cco@imon.agency · Яндекс` или `famesel7@gmail.com · Gmail`. Для международных площадок The Pending и Impactpool, а также англоязычных заявок система по умолчанию выбирает Gmail; для русскоязычных — корпоративную Яндекс Почту. Это эвристика по известному источнику/языку, не проверка гражданства или местонахождения заказчика. Всегда можно выбрать другой адрес.
- Ручной выбор запоминается отдельно для каждого объявления в локальном хранилище браузера и восстанавливается при повторном открытии.
- Кнопка «Открыть готовое письмо в Gmail» использует подтверждённый на Mac адрес `https://mail.google.com/mail/?view=cm&fs=1&to=...&su=...&body=...`. Gmail сам направляет в авторизованный аккаунт, не нужно указывать `/mail/u/<email>/`. Яндекс Почта открывает готовый черновик через `compose?mailto=...`. Письма отправляются только вручную, статус «Написал» автоматически не меняется.
- **Ограничение**: переключатель определяет почтовую службу/аккаунт, в котором откроется черновик, но браузер должен быть авторизован в соответствующем аккаунте. Перед отправкой обязательно сверить адрес в реальном поле «От», особенно если открыто несколько аккаунтов.
- Письма по Telegram-объявлениям не создаются на вымышленные адреса. Ограничение Telegram на холодные сообщения этот переключатель не обходит.

Проверка браузерного кода: `node tests/test_sender_channel.js`, плюс основной Python-набор `python3 -m unittest discover -s tests -q`.

### Переключатель перевода объявлений (29 октября 2026)

В карточке заказа с **англоязычным описанием** над исходным текстом появляется переключатель **English / Русский**. При выборе русского сервер выполняет машинный перевод опубликованного описания, при выборе английского — мгновенно возвращает исходный текст. Для русскоязычных заказов переключатель не показывается.

- Перевод вызывается **только по нажатию пользователя**. Внешнему сервису перевода передаётся **исходный текст публичного объявления**. Для непубличных и конфиденциальных ТЗ следует учитывать передачу текста стороннему провайдеру.
- Работает без дополнительного API-ключа: короткие части текста обрабатываются через публично доступный Google Chrome Translate endpoint, с запасными вариантами. Публичные неофициальные endpoints могут ограничивать частоту или менять формат, поэтому при недоступности в карточке отображается ошибка, а оригинал не подменяется.
- Перевод каждого исходного текста сохраняется в таблице SQLite `translation_cache` по хэшу содержимого. После изменения оригинала старый перевод не используется; после перезапуска сервиса уже сделанный перевод достаётся из кэша.
- Переключение не изменяет текст в SQLite-таблице `leads`, ссылку первоисточника, статусы, генерацию писем или email. Перевод носит справочный характер, особенно сроки, условия и имена нужно сверять с оригиналом.
- API: `POST /api/translate` с `{ "id": "<20-character-hex-id>", "target": "ru" }`, возвращает `translation` и признак `cached`. Разрешён только фиксированный целевой язык `ru`, никаких произвольных внешних URL или рекурсивных поисковых запросов.

Тесты: `python3 -m unittest discover -s tests -q` и `node tests/test_translation_ui.js`.

### Открытие готового письма в Gmail (29 октября 2026)

Пользователь выбрал самый простой рабочий процесс: **открывать готовый черновик Gmail**, а не отправлять SMTP-запросом из SearchOrders. Для зарубежных и англоязычных заказов по умолчанию выбирается `famesel7@gmail.com`; для остальных — `cco@imon.agency` (Яндекс). Адрес можно изменить вручную для любого объявления.

Кнопка **«✉ Открыть готовое письмо в Gmail»** строит стандартную ссылку `https://mail.google.com/mail/?view=cm&fs=1&to=...&su=...&body=...`. Она **проверена на Mac с авторизованным Gmail**: веб-интерфейс действительно открывает форму «Написать письмо» с корректными получателем, темой и текстом, без 404. Этот вариант заменяет некорректную ссылку с `/mail/u/famesel7%40gmail.com/?...&tf=cm`, а также убирает ненужные пароль приложения и локальную SMTP-отправку. Не нужно передавать SearchOrders ни обычный пароль Gmail, ни пароль приложения Google.

**Важно:** Gmail должен быть открыт в браузере под ожидаемым аккаунтом. Поле «От» внутри письма нужно проверить перед отправкой. Открытие черновика не подтверждает отправку, поэтому пользователь самостоятельно нажимает **«Отправить»** в Gmail и затем **«Написал»** в SearchOrders. Оригинальный текст и история заявок сохраняются. Если у браузера запрещены всплывающие окна, их необходимо разрешить для локального SearchOrders.

Тесты: `node tests/test_sender_channel.js` (каноническая ссылка Gmail, Unicode, заполнение полей, отсутствие автоматической отправки), `python3 -m unittest discover -s tests -q` (сервер не принимает прямые Gmail-письма).



### Бесплатные заявки и прямые контакты (29 октября 2026)
